# End-to-end results: spindoctor-qwerty-deepseek-harness 1.1.0

Run on 2026-10-11 (PT) in a clean-room copy (fresh clone in an empty folder, empty HOME and DSH_HOME, no access to engine
development folders), following only this README: `dsh plugin --profile web add ./spindoctor-qwerty-deepseek-harness`,
`dsh --profile web --dump-config`, `dsh plugin --profile web remove dsh-spindoctor-qwerty`, then `tests/dsh_host_check.py`.

**Mode: real host (DeepSeek Harness), model = local scripted stub.** `@deepseek-ai/dsh` **0.2.0-rc.2** (public preview, MIT, from
npm) on Linux with Node.js 22.19.0 and Python 3. No account, sign-in or API key was used. The model route was pointed at
`tests/stub_llm.py`, a local scripted OpenAI-compatible endpoint, through a `--patch` overlay on the `llm-pi-ai` and
`agent-default-model` rows (the documented pi-ai custom-gateway configuration); the overlay's `apiKeyEnv` value is a placeholder
the stub ignores. dsh offered the six tools to the model and executed four scripted calls through the plugin. dsh 0.2.0-rc.2 exits
silently on Node.js 20, so Node.js 22+ is required.

**Format check:** current harness docs (read 2026-10-11): `docs/user/develop/basic/publish.md` (bundle = `package.json` with
`dsh.bundle.patch`, `cordis.patch.yml` inserting rows by package name, install with `dsh plugin --profile <name> add`, check with
`--dump-config`, git installs fetch sources so built output needs a `prepare` script - not needed here, the bundle is plain JS),
`docs/user/develop/basic/tool.md` and `docs/cookbook/adding-a-tool.md` (`inject = ['tools']`, `ctx.tools.register(defineTool(...))`,
parameter DSL with explicit object openness, honour `exec.signal`, throw for infrastructure failures). Format unchanged from 1.0;
the parameter schemas were corrected to the DSL.

**Parity target:** the updated SpinDoctor 3.1.2. Publishing was approved by Russell on the basis of the updated 3.1.2 passing its
own suite 18/18, with the three 29-qubit test checks adapted to the 298-qubit limit.
